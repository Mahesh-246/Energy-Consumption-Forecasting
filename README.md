# PJMW Hourly Energy Consumption Forecasting

## Project overview

This project forecasts hourly electricity demand for the PJMW dataset. The Jupyter notebook explores and compares three machine-learning models:

- XGBoost
- LightGBM
- Random Forest

After comparing their evaluation results in the notebook, **XGBoost was selected for deployment because it performed best among these models in the project's evaluation**. The Streamlit application therefore uses XGBoost only. LightGBM and Random Forest remain part of the notebook/model-comparison work, not the deployed app.

## Repository files

- `code_file.ipynb` — Jupyter notebook containing data preparation, feature engineering, model training, evaluation, and model export.
- `app.py` — Streamlit dashboard for forecasting with the selected XGBoost model.
- `requirements.txt` — runtime dependencies for the XGBoost-only app.
- `PJMW_MW_Hourly.xlsx` — source dataset, if redistribution is permitted.
- `deployment/models.joblib` — trained XGBoost deployment bundle generated by the notebook's export cell.

## How the deployment works

The application loads the model bundle from `deployment/models.joblib`. The bundle must contain:
- `models["XGBoost"]`
- `history` with the `Datetime` and `PJMW_MW` columns
- `features["XGBoost"]` with the feature names expected by the trained model

The XGBoost forecast uses calendar features (`Hour`, `DOW`, `Month`, `Year`) and historical-demand lag features (`Lag_1`, `Lag_24`, `Lag_168`).

## Run locally

Use a Python environment compatible with your installed model libraries. From the repository root:

```bash
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Before running the app, run the notebook's XGBoost-only export cell and confirm that `deployment/models.joblib` exists.

## Deploy

Deploy `app.py` using a Streamlit-compatible hosting service. Ensure the deployed app can access `deployment/models.joblib`. If the model file is too large for normal GitHub upload, store it using a suitable model-storage option and adapt the loading code to retrieve it.

## Evaluation note

“XGBoost performed best” refers to the comparison results in this project's notebook. It should not be interpreted as a guarantee of future forecast accuracy. For claims about multi-day recursive forecasts, evaluate all candidate models using the same recursive forecasting procedure and forecast horizon.

## Data and model files

Do not commit API keys, credentials, virtual environments, or unrelated files. Upload the Excel dataset only if you have permission to redistribute it. Check GitHub and hosting-provider file-size limits before uploading `models.joblib`.
